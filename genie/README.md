## Tables

`city_metrics_all`, `neighbourhood_metrics_all`, `listings_all`, `predictions_all`, `model_evaluation`,

## The tricks

| Trick | Why |
|---|---|
| City A = Geneva, B = Zurich, C = Vaud; Vaud's neighbourhoods are municipalities | users ask about "City A", the data says "Geneva" |
| City totals only from `room_type = 'All'`; never sum or average the room-type rows; room-type questions use `room_type <> 'All'` | medians and distinct hosts do not add up. Without the last rule Genie answered "most common room type in Vaud" with `All` (100%) |
| Price statistics only on `has_price AND outlier_class <> 'implausible'`; "median" = `percentile(price, 0.5)` | inactive listings have no price; 14 implausible prices would distort averages |
| Exact room-type values; "entire homes" = `'Entire home/apt'` | users say "entire homes" or "flats"; the stored value is `'Entire home/apt'` |
| Neighbourhood price rankings only with `priced_listings >= 10` | without it, "most expensive municipalities in Vaud" was led by Commugny (6 listings, median CHF 1,246) |
| Model accuracy only on `label_ok AND split = 'test'`; under-priced = `error < 0` | train rows would flatter the model; the sign of `error` is easy to get backwards |
| "Where does the model under-price most" = by neighbourhood, most negative `avg(error)`, at least 15 test listings | turns a vague question into one query |
| `model_evaluation` has a combined `'A + B'` row; Vaud's numbers are in `city_c_report`; always show both Vaud runs and the baseline | Vaud's rows in `predictions_all` are the first run. Without the rule Genie reported only 68.1 for city C |
| 5 example question + SQL pairs, including the 4 questions of the assignment | Genie reuses verified SQL instead of writing it from scratch |
